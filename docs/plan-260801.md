# DT4LM 改进实验协议重构方案

本方案针对 2026-08-01 实验反馈，重新确定抽样协议、运行配置、逐样本
产物和评估边界。核心目标是：恢复 DT4LM 论文的随机测试集协议，公平比较
Base、Static、LexiDT、SemDT 和 Combined，并使所有论文指标都能从不可变的原始
产物离线重算。

## 1. 现有问题与处理结论

### 1.1 样本范围被错误缩小

当前 `statistics/prepare_manifests.py` 先让新旧模型遍历数据，只把两者都预测
正确的索引写入 manifest；`DifferentialClassification._should_skip_2` 又重复强制了
同一条件。这不是原始 DT4LM 的完整运行范围，也使方法无法在不同初始
预测状态上展示行为。

修改结论：

- test manifest 直接从完整 test split 中随机无放回抽样，不运行模型，不做
  clean-correct 预筛选。
- 测试集样本数 `sample_size` 缺省、为 `null` 或不大于 0 时使用全部；
  为正整数时随机抽取 `min(sample_size, split_size)` 条。
- 首轮 SST-2 和 RTE 均配置 `sample_size: 1000`；RTE 不足 1000 条时自然全量保留。
- 恢复原 DT4LM 的 skip 语义：只有原始输入已经满足“旧模型正确、新模型
  错误”时才记为 `skipped/already_differential`；其他三种初始状态都进入搜索。
- 自动阈值标定的训练集原始样本也按配置随机抽取，不做新旧模型
  共同正确预筛选。原始输入已经差分成功时自然不会产生扰动候选。

### 1.2 BERTScore 隐式下载与评估失败

当前评估器只调用 `bert_score.score(..., lang="en")`，无法配置本地模型路径；
运行器又把攻击与全部评估串成一个必须成功的命令。任意一个可选质量指标
失败，都会让已完成的攻击看起来像是无效实验。

修改结论：

- BERTScore 显式接收 `model_name_or_path`、`num_layers`、`device`、`batch_size`、
  `idf`、`rescale_with_baseline` 和 `baseline_path`。
- 默认 `allow_remote_download: false`。禁止远端下载时，`model_name_or_path` 必须是
  已存在的本地路径；使用自定义本地模型时显式配置 `num_layers`。
- 攻击、核心指标、质量指标分阶段落盘。核心指标先原子写入；BERTScore
  失败只把该 metric 记为 `failed`，不删除 `results.jsonl`，不使已完成的
  攻击失效。
- BLEU、METEOR、ROUGE-L 和 BERTScore 也各自记录状态、参数和错误，不使用
  一个笼统的 `--skip-bertscore` 运行时开关。

### 1.3 单次运行不应计算相对基线

当前 `run_improvements.py` 会寻找 Base summary，而 `evaluate_improvements.py` 包含
`compare_to_base` 和方法扩展判定。这让单次实验依赖另一个运行的目录名、
执行顺序和存在状态。

修改结论：

- 删除 `comparison_baseline`、`--base-summary`、`comparison_to_base` 和单运行内的扩展判定。
- 每个 run 只生成自身的标准化原始结果和绝对指标，不知道谁是 Base。
- 后续单独实现结果整理器，在读取多个已完成 run 时检查其 sample manifest
  hash、数据指纹、模型对、recipe、query budget 和 seed 是否可比，再计算成对
  差值、置信区间、表格和图。

### 1.4 配置分层没有带来实际收益

当前一次正式运行同时读取 dataset YAML 和 experiment YAML，实际上仍然需要人工
判断两个文件是否搭配。

修改结论：

- 一个 YAML 就是一次可独立执行的完整实验，不使用 YAML include、继承、模板或
  运行时 merge。
- `run_first_round.sh` 只接收一个实验配置。标定命令也读取同一份完整
  配置。
- 重复的通用字段在文件中显式复制。使用严格 schema 和跨配置一致性测试
  防止漂移，不用隐式合并节省几十行 YAML。
- 唯一例外是密钥文件：完整实验配置只引用被 Git 忽略的
  `*.secret.yaml`，运行产物仅保存脱敏后的 judge 身份。迁移期同时忽略旧的
  `*.secert.yaml` 拼写，但新配置不再使用该拼写。

## 2. 首轮方法与实验矩阵

方法定义保持不变：

- Base：DT4LM dynamic 目标 + Kuleshov 原约束。
- Static：`P_old(y|x') - P_new(y|x')`，不使用 `lambda1/lambda2`。
- LexiDT：预测状态、old/new margin 和负修改成本构成字典序目标。
- SemDT：Base 目标 + Kuleshov 原约束 + 双向 NLI 语义约束。
- Combined：LexiDT + 双向 NLI，只做兼容性与组合效果检查。

数据集为 SST-2 和 RTE，旧/新模型为 ALBERT base v1/v2，基础 recipe 为
`kuleshov_var`，每样本查询预算为 1000，首轮随机种子为 765。

每个数据集至少产生以下独立 run：

| run | 用途 |
| --- | --- |
| Base | 原 DT4LM 基线 |
| Static | 静态标量目标对照 |
| LexiDT | 字典序目标主结果 |
| SemDT-manual | 人工 `0.90/0.05` 阈值敏感性对照 |
| SemDT-openai | OpenAI-compatible judge 标定阈值，SemDT 主结果 |
| SemDT-hf | 本地 HF judge 独立标定阈值，用于复现 |
| Combined-openai | LexiDT + OpenAI 标定 NLI 阈值 |

所有同数据集 run 必须使用同一个 test sample manifest，才能进行逐样本成对
比较。同一 judge 标定与使用它的 SemDT/Combined 必须引用同一 threshold artifact
hash。

## 3. 随机样本协议

### 3.1 样本 manifest 与模型解耦

修正后的 sample manifest 只取决于数据集内容和抽样参数，不再取决于模型
预测。因此它应当与模型对解耦：

- sample manifest 不再包含 `old_model_id`、`new_model_id`、`eligible_indices` 和
  `eligible_count`。
- manifest 至少包含：`schema_version`、dataset ID/revision/fingerprint、split、
  `population_size`、`requested_sample_size`、`effective_sample_size`、seed、抽样算法版本、
  `selected_indices` 和内容 hash。
- 建议按 `SHA256(dataset_fingerprint, split, seed, index)` 对所有索引排序并取前
  `effective_sample_size` 条，实现跨 Python/NumPy 版本稳定的伪随机无放回抽样。
- 相同数据指纹、split、seed 和 `sample_size` 复用同一 manifest 是刻意设计，
  可以对不同方法乃至不同模型对做成对比较，不是身份混淆。

模型身份仍然必须保留在完整实验配置、run 目录、逐样本记录、标定
候选和阈值产物中。换言之，“抽什么样本”与“用什么模型攻击”分开记录。

### 3.2 测试集抽样语义

完整配置中使用以下固定口径，不再提供 `all/random_exact/random_up_to`
三种策略：

```yaml
dataset:
  evaluation:
    split: test
    sample_size: 1000  # 缺省、null 或 <=0 代表全部
    sample_seed: 765
    manifest: outputs/dt4lm-improvements/sample_sets/sst2/test-n1000-seed765.json
```

生成 manifest 时先检查 split 和数据指纹，然后按上述规则生成固定顺序。
不加载 tokenizer 或模型，不生成预测缓存。

### 3.3 标定原始样本抽样

标定候选收集使用独立的 train sample manifest：

```yaml
calibration:
  source_sampling:
    split: train
    sample_size: 500
    sample_seed: 765
    manifest: outputs/dt4lm-improvements/sample_sets/sst2/train-n500-seed765.json
```

`sample_size` 使用与 test 相同的“至多 N 条”语义。收集阶段对这些原始样本运行
Base 轨迹，记录通过原约束、预算截断后确实要查询的候选。后续的 1000
条候选分层抽样、800/200 冻结划分、precision 下限和补充审计协议保持不变。

标定报告要额外列出源原始样本的 success/failed/skipped 数量和各初始预测
状态数量，避免候选数量不足时被误判为标注器问题。

## 4. 初始状态与逐样本产物

### 4.1 状态定义

每个随机样本初次查询后必须归入且仅归入以下一种状态：

| `initial_state` | 新模型 | 旧模型 | 处理 |
| --- | --- | --- | --- |
| `both_correct` | 正确 | 正确 | 进入搜索 |
| `new_correct_old_wrong` | 正确 | 错误 | 进入搜索 |
| `both_wrong` | 错误 | 错误 | 进入搜索 |
| `already_differential` | 错误 | 正确 | 记为 skipped，不把原句伪装成生成成功 |

搜索成功条件仍然是候选上旧模型正确且新模型错误，没有改变方法
本身的差分目标。

### 4.2 `results.jsonl` 协议

每个 manifest 索引必须恰好对应一条记录，完成 run 必须满足
`N = successful + failed + skipped`。建议升级为以下版本化 schema：

```text
schema_version, run_id, experiment_id
dataset_id, split, dataset_fingerprint, sample_manifest_hash
dataset_index, sample_order, ground_truth_label
initial_state, result_status, skip_reason
original_input, candidate_input
original_new_output, original_old_output
final_new_output, final_old_output
objective_name, objective_score
modified_indices, modification_rate
model_pair_queries, initial_model_pair_queries, search_model_pair_queries
queries_to_success
wall_clock_seconds, peak_vram_bytes
nli, nli_profile
error_type, error_message
```

具体要求：

- `result_status` 只取 `successful/failed/skipped`；攻击程序异常不冒充样本结果，
  run 记为 `incomplete`并保留可恢复检查点。
- `attack_summary.json` 和 `metrics/core.json` 都必须显式保存 `successful`、
  `failed`、`skipped` 及 `total`，不能只保存成功率或依赖目录文件数反推。
- `queries_to_success` 只在成功时为整数，失败和跳过时为 `null`。绘制曲线
  时不从文本日志猜测查询数。该值是成功出现时累计的模型对查询数，包含原始
  输入的初始模型对查询；一个新旧模型对的联合查询记为一个逻辑查询单位。
- `model_pair_queries` 包含初始查询，并与逻辑候选数而非 batch 数一致。
- 原始和最终的新旧输出都记录预测标签、概率、可用 logits 和 margin。
- 记录时不再依赖目录名表示方法、数据或模型身份。

## 5. 评估指标与论文产物

### 5.1 计数和分母

对一个完成 run，定义：

- \(N\)：manifest 中全部随机样本数；
- \(K\)：`skipped/already_differential` 数；
- \(A=N-K\)：真正进入扰动生成的样本数；
- \(S\)：成功生成的差分输入数；
- \(F\)：进入搜索但最终失败的数量。

完整性条件为 \(N=S+F+K\) 且 \(A=S+F\)。

主要报告两个不混淆的效果口径：

\[
\mathrm{PaperGSR}=\frac{S}{S+F},
\]

该指标与原 TextAttack/DT4LM 的 attack success rate 分母一致，是论文对比主口径。

\[
\mathrm{SampleGenerationRate}=\frac{S}{N},
\]

该指标表示从完整随机样本中实际新生成差分输入的比例。同时报告
`PreexistingDifferentialRate = K/N` 和四种 `initial_state` 分布。

### 5.2 查询效率和 success-query curve

对查询预算 \(B\)，主口径为：

\[
\mathrm{Success@B}
=
\frac{\#\{i:\mathrm{successful}_i\land q_i^{success}\le B\}}{A}.
\]

首轮表格保留 `Success@100`、`Success@500` 和 `Success@1000`。另外从
`queries_to_success` 计算完整曲线：

\[
C(b)=
\frac{\#\{i:\mathrm{successful}_i\land q_i^{success}\le b\}}{A},
\quad 1\le b\le Q_{max}.
\]

本轮不实现 success-query curve 图片绘制。原始 run 必须保留每个样本的
`result_status`、`queries_to_success`、`model_pair_queries` 和 query budget，并在
`metrics/core.json` 中保存曲线定义所需的分母 \(N/A\)，并在
`metrics/success_queries.json` 中以 `Dict[List]` 保存成功样本索引与查询数。后续
整理器可据此选择任意横轴间隔绘图，不能依赖文本日志或预先固化的图片数据。

机器可读核心指标同时输出
`SampleSuccess@B = #success(q_success <= B) / N`，便于衡量一批随机输入在给定
预算下的实际产出率；论文主表仍以攻击口径的 `Success@B` 为主，避免同名指标
混用不同分母。计数分子、(N) 和 (A) 均须落盘，使两种口径可离线复算。

可在主表中增加一个早成功综合指标：

\[
\mathrm{SQ\text{-}AUC}
=
\frac{1}{Q_{max}}
\sum_{b=1}^{Q_{max}} C(b).
\]

它的范围为 `[0,1]`，越大表示成功率更高且更早成功。同时报告成功样本
查询数的 median 和 IQR。

QPS 保持已确认的口径：

\[
\mathrm{ModelPairQPS}
=
\frac{\sum_{i=1}^{N}q_i}{S}.
\]

分子包含完整随机样本上发生的全部模型对查询，包括失败样本和 skipped
样本的初始查询；\(S=0\) 时为 `null`，并保留 `model_pair_query_total`。

### 5.3 修改幅度、质量和语义

只在成功生成样本上计算：

- AMR：平均词级修改率；
- BLEU、METEOR 和 ROUGE-L；
- BERTScore precision/recall/F1；
- 成功样本的 NLI 分数与阈值通过率，作为自动诊断，不替代人工评估。

人工评估仍按 Base/SemDT 共同成功、Base 独有成功和 SemDT 独有成功三层
抽样 100 个原始样本，保持方法内的实际分层权重和成对 bootstrap。报告：

- 成功输入中的加权语义保持率；
- `ValidGSR = 估计语义有效成功数 / N`，保留之前确认的完整随机
  样本分母；
- 补充 `ValidPaperGSR = 估计语义有效成功数 / A`，与
  `PaperGSR` 对齐；
- 两者的分层 bootstrap 95% 置信区间。

### 5.4 资源开销与标定质量

每个 run 报告：

- 总 wall-clock time、每个成功输入时间、峰值显存；
- NLI 候选数、方向句对数、batch 数、缓存命中率、截断数和耗时；
- 目标模型查询与 NLI 推理开销分开，不用 QPS 掩盖 SemDT 的附加成本。

每个标定后端报告阈值、搜索集结果、冻结验证集的 precision/recall/
混淆矩阵与 bootstrap 95% 置信区间、标注失败率、接受率、补充审计结果和
正式 SemDT 轨迹偏移审计。

### 5.5 预先确定的论文表图

为了避免运行后再临时定义指标，首轮固定以下产物：

1. 主结果表：Dataset、Method、N/A/S/F/K、PaperGSR、SampleGenerationRate、
   Success@100/500/1000、SQ-AUC、AMR、ModelPairQPS。
2. 语义与质量表：BLEU、METEOR、ROUGE-L、BERTScore F1、人工语义保持率、
   ValidGSR 和 ValidPaperGSR，人工指标附 95% 置信区间。
3. 资源表：模型对查询总数、运行时间、每成功时间、峰值显存和 NLI profile。
4. 标定表：judge 身份、阈值、搜索/验证 precision 和 recall、标注失败率、
   补充审计和轨迹偏移结果。
5. success-query curve 原始数据：逐样本状态与成功查询数，以及每个 run 的
   \(N/A\)、query budget 和成功查询数列表。本轮不生成图片；后续整理阶段再为
   SST-2 和 RTE 绘图。

## 6. 单文件完整实验配置

### 6.1 目录与命令

建议将现有 dataset/experiment 两层配置替换为：

```text
experiments/improvements/configs/
  sst2/
    albertbasev1-v2-base.yaml
    albertbasev1-v2-static.yaml
    albertbasev1-v2-lexidt.yaml
    albertbasev1-v2-semdt-manual.yaml
    albertbasev1-v2-semdt-openai.yaml
    albertbasev1-v2-semdt-hf.yaml
    albertbasev1-v2-combined-openai.yaml
  rte/
    ...
```

运行接口统一为：

```bash
bash experiments/improvements/prepare_manifests.sh <experiment.yaml>
bash experiments/improvements/calibrate_semdt.sh <experiment.yaml>
bash experiments/improvements/run_first_round.sh <experiment.yaml>
```

Base/Static/LexiDT 配置的 `calibration.enabled` 为 false；对它们调用标定命令应
明确失败。不再从第二个 YAML 合并字段。

### 6.2 建议 schema

以 `SemDT-openai` 为例，一份完整配置包含：

```yaml
schema_version: 2

experiment:
  id: sst2-albertbasev1-v2-semdt-openai
  method: semdt
  seed: 765
  output_root: outputs/dt4lm-improvements

dataset:
  id: sst2
  path: outputs/datasets/sst2
  revision: null
  text_columns: [sentence]
  label_column: label
  task_definition: Classify the sentence sentiment as negative or positive.
  evaluation:
    split: test
    sample_size: 1000
    sample_seed: 765
    manifest: outputs/dt4lm-improvements/sample_sets/sst2/test-n1000-seed765.json

models:
  id: albertbasev1-v2
  old:
    name_or_path: outputs/albertbasev1_sst2/best_model
    revision: null
  new:
    name_or_path: outputs/albertbasev2_sst2/best_model
    revision: null

attack:
  recipe: kuleshov_var
  differential_objective: dynamic
  semantic_constraint: nli
  query_budget: 1000

semantic:
  nli:
    model_name_or_path: /models/roberta-large-mnli
    revision: null
    allow_remote_download: false
    device: cuda
    dtype: float32
    batch_size: 32
    candidate_batch_size: 1024
    max_length: 512
    truncation_strategy: longest_first
  threshold:
    source: calibrated
    artifact: outputs/dt4lm-improvements/calibration/sst2/albertbasev1-v2/openai/threshold.json

calibration:
  enabled: true
  output_dir: outputs/dt4lm-improvements/calibration/sst2/albertbasev1-v2/openai
  source_sampling:
    split: train
    sample_size: 500
    sample_seed: 765
    manifest: outputs/dt4lm-improvements/sample_sets/sst2/train-n500-seed765.json
  candidate_collection:
    recipe: kuleshov_var
    differential_objective: dynamic
    semantic_constraint: original
  candidate_sample_size: 1000
  search_sample_size: 800
  minimum_validation_positives: 100
  maximum_total_labels: 2000
  trajectory_sample_size: 100
  annotation_batch_size: 32
  threshold_search:
    method: grid
    step: 0.01
    min_precision: 0.95
    bootstrap_samples: 10000
  judge:
    backend: openai
    config_file: configs/openai.secret.yaml

evaluation:
  core:
    success_budgets: [100, 500, 1000]
  quality:
    bleu: {enabled: true}
    meteor: {enabled: true}
    rouge_l: {enabled: true}
    bertscore:
      enabled: true
      model_name_or_path: /models/roberta-large
      num_layers: 17
      allow_remote_download: false
      device: cuda
      batch_size: 32
      idf: false
      rescale_with_baseline: false
      baseline_path: null
```

条件校验要求：

- `semantic_constraint: nli` 时必须有 `semantic.nli` 和 threshold；`original` 时不需要。
- `threshold.source: calibrated` 时 artifact 必须存在且身份一致；`manual` 时配置
  entailment/contradiction 值。
- `calibration.enabled: true` 时必须具备完整标定字段；false 时不允许遗留
  会影响运行的标定字段。
- 每个配置必须有全局唯一 `experiment.id`，不允许通过修改目录名隐式改变
  实验身份。
- 配置文件在运行前先解析为 `config.resolved.yaml` 并计算 hash；因为不存在
  merge，resolved 版本与输入只有路径规范化和脱敏差异。

## 7. 标准化运行产物

每个 run 使用：

```text
outputs/dt4lm-improvements/runs/<dataset>/<models.id>/<experiment.id>/
  config.resolved.yaml
  provenance.json
  status.json
  sample_manifest.json
  results.jsonl
  attack_summary.json
  metrics/
    core.json
    success_queries.json
    quality.json
  successful_examples/
  failed_examples/
  skipped_examples/
  nli_candidates.jsonl
  nli_profile.json
```

`status.json` 分别记录 `attack`、`core_evaluation`、`quality_evaluation` 的
`pending/running/completed/failed`。约束如下：

- 只有 attack completed 且 `results.jsonl` 覆盖 manifest 全部索引时，该 run 才可
  进入论文结果整理。
- `core.json` 不依赖 NLTK、BERTScore 或网络，并内嵌资源指标，必须在 attack 后立即可算。
- `success_queries.json` 使用等长列数组保存绘图原始数据，不塞入 `core.json`。
- 质量指标一项失败不覆盖其他指标。四项指标统一保存在 `quality.json`，但不把
  缺失值伪装成 0。
- 不读取其他 run，不写相对 Base 指标，不在 run 阶段决定方法是否达到
  扩展标准。

## 8. 结果整理器的输入契约

结果整理由 `statistics/aggregate_improvements.py` 实现。它只读已完成 run，不调用
受测模型、NLI 或 judge，也不在这一阶段计算相对 Base 指标。

聚合前必须检查每个 run 的 v3 schema、manifest 样本数、成功数和
`success_queries.json` 等长列一致。dataset fingerprint、manifest hash、old/new
model revision、recipe、query budget 和 seed 均作为 CSV 列保留，供后续成对分析
检查可比性；本整理器本身不计算成对差值。

聚合器输出一个宽格式 CSV，每行为一个 dataset-model_pair-method-seed run，包含
论文主指标、质量、资源、状态与复现信息。success-query curve 继续读取各 run 的
列式原始数据，图片绘制不属于本轮实施范围。
- 以 dataset index 为单位的成对 bootstrap 差值与 95% 置信区间；
- 二元成功差异的成对计数，为 McNemar 或其他预注册检验提供输入；
- 不把结果选择或“达标”逻辑写回原 run。

## 9. 实施步骤

### 阶段 1：冻结协议测试

1. 从 `DT4LM-master` 原始实现建立 skip、GSR 分母和 1000 条运行协议的回归测试。
2. 为随机抽样、逐样本 schema、查询曲线和评估分阶段先写失败测试。
3. 定义 `schema_version: 2`，禁止新旧产物在同一聚合中混用。

### 阶段 2：替换 manifest 生成

1. 删除 manifest 生成器中的 tokenizer/模型加载、预测和 `_jointly_correct`。
2. 实现缺省/非正数全量、正数至多 N 条的稳定随机抽样。
3. 分别生成 test sample manifest 和 calibration train sample manifest。
4. 修改 `SampleManifest`/`ManifestDatasetView`，仅验证数据身份、顺序和索引范围。

### 阶段 3：恢复搜索范围并升级日志

1. 将 `_should_skip_2` 恢复为只跳过 `already_differential`。
2. 在初始查询后保存四种 `initial_state` 及初始新旧输出。
3. 完整记录 status、skip reason、查询分解和 `queries_to_success`。
4. 让 success/failed/skipped 都有独立结构化产物，并保证每个 manifest 索引一条记录。

### 阶段 4：合并配置与简化运行器

1. 实现单个严格完整配置解析器及条件校验。
2. 为 SST-2/RTE 的每个 run 创建独立完整 YAML。
3. 把三个 shell 入口改为只接收一个实验配置。
4. 删除运行时的 Base 搜索、相对指标和方法达标判定。

### 阶段 5：拆分评估并修复 BERTScore

1. 先从 `results.jsonl` 原子写入内嵌资源的 `core.json` 和列式
   `success_queries.json`。
2. 实现 Success@B、success-query curve 原始数据、SQ-AUC、状态分布和新 GSR 口径；
   不实现曲线图片绘制。
3. 将 BLEU、METEOR、ROUGE-L、BERTScore 集中写入一个 `quality.json`，保留每项
   独立状态与 checkpoint。
4. 为 BERTScore 传入完整本地模型配置，默认禁止隐式网络访问。
5. 保证质量指标失败不损坏攻击产物或核心指标。

### 阶段 6：迁移标定、人工评估和文档

1. 让候选收集使用新 train sample manifest，去除共同正确筛选。
2. 保留标定的 1000、800/200、补充审计和双后端独立协议。
3. 让人工评估适配 N/A/S/F/K 及 ValidPaperGSR，不改变原有三层盲评。
4. 重写完整中文指南，删除旧的两配置命令和 jointly-correct 口径。

### 阶段 7：结果整理器

实现多 run 绝对指标聚合和论文 CSV。成对统计与 success-query curve 绘图仍留到
后续任务；本轮只保证原始数据
完整、稳定且可离线重算。整理器不回写或修改任何原始 run。

## 10. 验收测试

必须至少覆盖：

- `sample_size` 缺省、`null`、0 和负数时全量；正数小于/等于/大于 split 数量
  时分别产生预期样本数。
- 相同数据指纹、seed 和数量生成完全相同的索引和顺序；改变任一项时
  manifest hash 变化。
- manifest 生成途径不导入 Transformers，不加载或查询模型。
- 四种初始预测状态均有回归测试；只有 `already_differential` 被跳过。
- 逐样本记录正好覆盖 manifest，并满足 N=S+F+K；缺行、重复行或多余行
  都使核心评估失败。
- 手算小样本上 PaperGSR、SampleGenerationRate、Success@B、SQ-AUC、QPS、
  AMR 与曲线坐标完全一致。
- 每个成功样本的 `queries_to_success` 不大于 query budget；失败/跳过为 null。
- 两个方法的 success-query 原始数据能在同一 manifest 上成对重算，按定义得到的
  曲线终点等于各自 PaperGSR；测试不生成图片。
- BERTScore 能使用临时本地模型路径；禁止网络时不尝试远程下载。
- BERTScore 故意失败后，`results.jsonl`、`core.json` 与其他质量指标仍可用，
  `status.json` 只标记对应 metric 失败。
- 单 run 输出不包含 Base 路径、相对差值或扩展决策。
- 每个完整 YAML 能独立通过 schema 校验并生成唯一 run 目录；删除任一
  必需字段都在发起模型查询前失败。
- 结果整理器对 manifest/model/revision/budget 不一致的 run 拒绝比较。

## 11. 迁移与完成标准

- 现有 jointly-correct manifest 与 `schema_version: 2` 不兼容，必须重新生成；
  旧产物保留为历史记录，不就地改写。
- 现有 `configs/sst2.yaml`、`rte.yaml` 和 `configs/experiments/*.yaml` 在新完整配置
  经过验证后删除，不长期维护两套入口。
- 新 run 必须使用新 `experiment.id` 和 schema 目录，不与旧 summary 混合。
- 完整实验必须先有可用的 `results.jsonl` 和 `core.json`；质量指标可重试，
  但论文汇总前要求预注册为 enabled 的指标全部 completed。
- 中文指南、配置示例、CLI `--help` 和测试必须同步反映单配置、随机
  抽样、状态分母和离线评估协议。
