有问题，但**核心研究方向没有错**。主要问题是：首轮范围被重新扩张了，而且有几处会直接影响实验有效性。当前计划不建议原样执行。

## 必须修改的问题

### 1. RTE 无法固定抽取 500 个测试样本

原论文划分后的 RTE 测试集总共只有 **277 条**，还要进一步筛选“新旧模型均正确”的样本，因此不可能得到 500 条合格测试样本。

应改为：

* SST-2：从合格样本中固定抽取 500 条；
* RTE：使用测试集中全部合格样本；
* GSR、Success@B 的分母使用各数据集 manifest 中的实际样本数 (N_D)，不能写死为 500。

[
\mathrm{GSR}*D=\frac{N*{\mathrm{success},D}}{N_D}
]

“合格样本少于500立即报错”必须删除。

---

### 2. LexiDT 和 Base 使用不同搜索实现，会混淆实验结论

当前设计是：

* Base：原 `GreedySearch`；
* LexiDT：新 `LexicographicGreedySearch`。

即使二者都是贪心搜索，它们在以下方面仍可能不同：

* 候选排序；
* 查询预算截断；
* tie-breaking；
* 异常处理；
* 无候选时的返回逻辑；
* 同轮多个成功输入的处理。

这样 LexiDT 的收益可能来自搜索代码变化，而不完全来自字典序目标。

应实现一个统一的、支持自定义比较器的贪心搜索：

```text
ComparatorGreedySearch
├── ScalarComparator       # dynamic/static
└── LexicographicComparator # LexiDT
```

然后让 Base、Static 和 LexiDT 都通过同一搜索实现。Dynamic 模式必须通过 golden test 证明其候选选择、成功结果和查询数与原实现一致。

---

### 3. LexiScore 仍然缺少显式预测状态

当前三元组为：

[
(g_{\mathrm{old}},g_{\mathrm{new}},-c)
]

当 margin 恰好为 0 时，截断结果也是 0，但 argmax 在并列情况下不一定满足目标条件。因此，“margin目标已满足”和“预测条件已满足”不能完全等价。

建议使用：

[
G_{\mathrm{LexiDT}}(x')
=======================

\left(
I_{\mathrm{old}},
g_{\mathrm{old}},
I_{\mathrm{new}},
g_{\mathrm{new}},
-c
\right)
]

其中：

[
I_{\mathrm{old}}
================

\mathbf 1[\operatorname{pred}_{old}(x')=y]
]

[
I_{\mathrm{new}}
================

\mathbf 1[\operatorname{pred}_{new}(x')\neq y]
]

这样排序依次表示：

1. 旧模型是否真的正确；
2. 旧模型尚未正确时，距离正确边界多远；
3. 新模型是否真的错误；
4. 新模型尚未错误时，距离错误边界多远；
5. 修改成本。

对应实现应为：

```python
return (
    int(old_pred == gold_label),
    min(old_margin, 0.0),
    int(new_pred != gold_label),
    min(new_margin, 0.0),
    -modification_cost,
)
```

---

### 4. 不应通过数值范围猜测输出是 logits 还是概率

计划目前通过以下规则自动判断：

> 所有值位于 `[0,1]` 且行和约等于1，就认为是概率，否则认为是logits。

这不够可靠。某组logits在数值上也可能偶然满足该条件，且不同wrapper可能已经内部执行softmax。

应让模型wrapper显式声明输出类型：

```python
ClassificationModelOutput(
    scores=...,
    score_type="logits",  # 或 probabilities
)
```

对于Hugging Face分类模型，直接读取模型返回对象中的 `.logits`；对于自定义wrapper，要求显式配置，禁止依靠数值启发式判断。

---

### 5. 阈值标定存在数据自适应和分布偏移问题

当前方案先检查验证集中是否至少有100个正例；不足时扩展到2000条，然后对完整数据重新做80%/20%划分。这等于根据验证结果修改数据规模并重新划分，验证集不再完全独立。

此外，标定候选来自 Base 的动态搜索轨迹，但 SemDT 加入NLI后会改变后续搜索轨迹，因此正式运行时的候选分布可能与标定数据不同。

建议简化为：

1. 固定标注1000条，不根据验证结果重新划分；
2. 一开始就固定800条阈值搜索集和200条验证集；
3. 在搜索集上选择阈值；
4. 在200条验证集上只报告结果；
5. 阈值确定后，在 SemDT 实际搜索轨迹中额外抽取少量候选，例如100条，做一次独立LLM审计，仅检查分布迁移，不再调阈值。

如果验证精度不够稳定，再追加一个新的独立审计集，不能重新混合原验证数据。

另外，候选观察器必须放在：

```text
原有约束通过
→ 查询预算截断
→ 记录实际即将查询的候选
→ 模型查询
```

否则可能记录因预算不足而根本没有被搜索算法评估的候选。

---

## 需要明确但不阻塞实现的问题

### 6. 当前GSR与原论文的GSR不是同一口径

计划只测试“原始输入上新旧模型都正确”的样本。这有利于研究**扰动诱发的新回归**，但它比原论文的候选范围更严格。

因此应额外报告：

[
\mathrm{EligibilityRate}
========================

\frac{#{\text{新旧模型原始输入均正确}}}
{#{\text{测试集样本}}}
]

并把指标称为：

```text
Perturbation-induced GSR
```

不能把该数值与原论文表格中的GSR直接作绝对比较。所有内部方法仍使用相同manifest，因此 Base、SemDT、LexiDT之间的比较是公平的。

---

### 7. QPS无法体现SemDT的真实成本

QPS只统计新旧目标模型查询，不统计NLI，这是为了与DT4LM指标兼容，可以保留。但SemDT可能通过大量NLI推理换取较少的目标模型查询。

因此必须并列报告：

* Model-pair QPS；
* NLI方向句对数；
* 端到端wall-clock time；
* 峰值显存；
* 每个成功输入的总运行时间。

SemDT的验收标准不能只写“QPS增幅不超过30%”，至少还应要求端到端时间没有出现不可接受的数量级增长；首轮可以先报告，不必预设一个武断阈值。

---

### 8. NLI缓存键还不完整

目前缓存键只有：

```text
(model_revision, original_text, candidate_text)
```

建议加入：

```text
tokenizer_revision
max_length
truncation_strategy
```

否则修改截断设置后，可能错误复用旧分数。

还应记录被截断候选的数量。RTE通常较短，但框架本身不能静默截断而不留痕迹。

---

### 9. 人工评估中的极小分层会低估不确定性

当前要求非空小层至少抽1条，但如果某层只有1个人工样本，层内bootstrap无法反映该层的不确定性。

建议：

* 每个被单独估计的非空层至少抽5条；
* 若按比例不足5条，则合并稀有层，或明确将其全部纳入；
* 总人工样本仍控制在每个数据集100个左右。

---

## 计划中正确、可以保留的部分

以下设计是合理的：

* SemDT与LexiDT保持模块独立；
* Combined只做兼容性检查；
* Static公式定义正确；
* 新模型margin方向已经修正；
* 修改成本沿用DT4LM的词级修改率；
* NLI放在原有约束之后、目标模型查询之前；
* LLM只用于离线阈值标定；
* 阈值以高precision约束下最大化recall；
* 固定manifest保证所有方法使用相同样本；
* ValidGSR采用分层人工评估直接估计；
* API密钥、产物恢复、结果schema和回归测试设计较完善。

## 建议的首轮最小范围

最终应压缩为：

```text
数据集：
- SST-2：500个合格样本
- RTE：全部合格测试样本

实验：
- Base
- Static
- SemDT-manual
- SemDT-openai
- LexiDT
- Combined（最后再运行）

Judge：
- 只实现OpenAI后端
- HF仅保留接口

模型：
- 只实现并验证ALBERT v1/v2
- 未来模型只定义统一输出协议，不在首轮实现适配

搜索：
- 所有目标共用ComparatorGreedySearch
```

所以最终判断是：方案的方法逻辑基本成立，但存在一个无法执行的问题（RTE 500条）、两个会污染实验归因的问题（不同搜索实现、缺少显式预测状态）。
